### Expected income and moved salaries

Use qualifying booked credits from the previous income window. For start day `d > 1`, that previous cycle is `[date(M−2, d), date(M−1, d) − 1 day]`; for the default day 1 it is the previous calendar month. The current cycle uses the same window as budget-start income, so an expected salary on 26 November funds December and never enters November's expected items, total or pace budget. The existing recurring detector accepts expense debits. Partition qualifying prior and current credits by selected category and currency, with receiving account and normalized structured debtor name as internal matching evidence. Normalize with Unicode normalization, whitespace collapsing and case folding. Each prior credit can contribute one estimate, and each current credit can consume at most one prior credit. Never use amount or day to break a tie. `hestia/budget/recurring.py:152–166,179–200`, `hestia/budget/month_budget.py`

1. First match a unique prior credit and a unique current credit for the same receiving account and nonempty normalized debtor name. Remove both from further matching.
2. Among unmatched rows, consume a prior credit with a current credit from a different selected account only when there is exactly one unmatched prior and one unmatched current credit for the same nonempty name in the category and currency, and there is no unresolved local ambiguity for the name. Local ambiguity means that after step 1 an account has both prior and current credits for that name in that category and currency, with more than one credit on at least one side. An account with only prior or only current credits can proceed to cross-account matching. A salary paid into account B then appears as actual income in B and consumes the old estimate from A even if the amount changed.
3. If several credits could complete a match, suppress the pending estimates for that name and any unnamed prior credits in the partition. For indistinguishable or unnamed prior credits, a combined prior subtotal with no expected day is allowed only when there are zero current qualifying credits in that category and currency. Mark this fallback partial. With no prior evidence for a configured category, indicate missing evidence. `unavailable` means there is no prior estimate to evaluate. `none` means evidence shows no pending amount or the configured set is empty. `hestia/budget/analytics_views.py:107–117,175–193,499–501,546–553`, `hestia/budget/analytics_core.py:101–112`

### Pace

Report no funded budget when `B <= 0`, already reached when `B > 0` and `S >= B`, no positive pace when `B > 0` and `S <= 0`, exhaustion when a future day qualifies, or within budget at this pace.
