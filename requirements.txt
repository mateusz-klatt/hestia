# hestia runtime dependencies.
#
# The Keemple protocol/command/state codec stays pure-stdlib first-party code (the
# clean-room asset). These are vetted GENERIC-infrastructure libraries adopted now
# that hestia ships in a container (the old bare-metal zero-deps rule is relaxed):
#
#   cryptography — AES-128-ECB primitive for the Tuya v3.3 client (hestia/tuya.py).
#                  Tuya framing / PKCS7 / version header / device22 quirks remain
#                  first-party; only the block cipher comes from the library.
#   pyserial     — USB-CDC serial transport for the Flipper Zero RPC client
#                  (hestia/flipper.py). The RPC framing / protobuf codec stay first-party.
#   aiohttp      — in-loop HTTP/SSE web UI transport. The Keemple codec stays
#                  pure-stdlib first-party code.
#   SQLAlchemy   — typed ORM + engine for the SQLite persistence layer (#57). Sync
#                  engine driven off the event loop via run_in_executor; the schema
#                  is Alembic-managed. The Keemple codec / state model stay first-party.
#   alembic      — schema migrations for the SQLite DB (run programmatically at startup).
#   pydantic     — typed DTOs for the PUBLIC API contract (hestia/api_contract.py) → generated
#                  OpenAPI for typed clients (web TS + the iOS "Vesta" app). Wire-shape only; the
#                  authoritative validators (web._validate_control_payload, automations.Rule.from_dict)
#                  stay first-party and a test pins the DTOs to them.
